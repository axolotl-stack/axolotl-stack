# game-data Specification

## Purpose
`crates/unastar-data` turns pinned Bedrock data sources into the typed, source-attributed tables the server reads: blocks, items, biomes, actor definitions and components, loot tables, recipes, spawn rules, commands, game rules, shapes and measured BDS facts. It covers the sources and their priority, the build-time generation into `OUT_DIR`, the committed artefacts and manifests, the offline `datagen` (`unastar-data-gen`) and `codegen` (`unastar-data-codegen`) tools, and the BDS pack comparison. How pack files are parsed belongs to `pack-loader` and how rules evaluate to `rules-engine`. Measured facts come from `crates/bds-extractor` (join-packet captures) and from `crates/bds-sweep` with `tools/bds-sweep` (scripted BDS sweeps). Why: decisions [0011](../../../docs/decisions/0011-pin-vanilla-packs-to-bedrock-samples-1-26-50.md), [0012](../../../docs/decisions/0012-codegen-schemas-decode-vanilla-data-at-startup.md), [0014](../../../docs/decisions/0014-measure-built-in-facts-from-bds.md), [0015](../../../docs/decisions/0015-vanilla-scope-with-extensible-registries.md) and [0024](../../../docs/decisions/0024-do-not-commit-eula-derived-artefacts.md).

## Requirements

### Requirement: Pinned inputs are required to build
The `unastar-data` build script SHALL read vanilla pack data only from the bedrock-samples submodule at `data/vanilla_bp` (version 1.26.50.4) and native BDS 1.26.51 measurements only from the protocolgen submodule's `data/source/inputs/1.26.51/native`. If either is missing the build MUST fail with a message naming the `git submodule update --init` command, instead of building without data.

#### Scenario: Missing samples submodule
- **WHEN** `data/vanilla_bp/behavior_pack/entities` or `biomes` does not exist
- **THEN** the build panics with a message telling the user to run `git submodule update --init crates/unastar-data/data/vanilla_bp`

#### Scenario: Missing protocolgen submodule
- **WHEN** `native/biome_id_map.json` does not exist
- **THEN** the build panics with a message naming `crates/valentine_gen/protocolgen`

Evidence: crates/unastar-data/build.rs, crates/unastar-data/output/manifest.kdl, crates/unastar-data/data/bds_pack_diff.json (`pins`)

### Requirement: Pack-derived data is generated into OUT_DIR, never committed
Data derived from the vanilla packs (actor definitions, component registry, schema defaults and typed bodies, pack-enriched biomes, loot tables, item and recipe bundles, spawn rules) SHALL be generated by `build.rs` into Cargo's `OUT_DIR` and embedded from there. No per-entry pack-derived JSON, KDL or Rust MUST be committed; only counts and hashes go in `output/pack-manifest.json`. The build MUST rerun when any input file or input directory changes.

#### Scenario: Embedded from OUT_DIR
- **WHEN** `actor_definitions`, `biomes`, `loot`, `spawn_rules`, `item_components`, `recipes` and `actor_components` are compiled
- **THEN** each embeds its data with `include_bytes!` or `include!` from `OUT_DIR`

#### Scenario: Adding a pack file invalidates the build
- **WHEN** a file is added to the samples `entities` directory
- **THEN** Cargo reruns the build script because it watches the directory as well as each input file

Evidence: crates/unastar-data/build.rs, crates/unastar-data/build/actors.rs, crates/unastar-data/build/loot.rs, crates/unastar-data/build/biomes.rs, crates/unastar-data/build/items_recipes.rs, crates/unastar-data/build/spawn_rules.rs, crates/unastar-data/src/actor_definitions.rs (`VANILLA_JSON`), crates/unastar-data/src/loot.rs (`VANILLA_JSON`), crates/unastar-data/src/biomes.rs (`VANILLA_JSON`)

### Requirement: Hash and count ratchet for generated pack data
`output/pack-manifest.json` SHALL record a count and SHA-256 for each embedded pack-derived family it lists, written by `unastar-data-gen --manifest-only`. A test MUST fail when the build's actor component registry, actor definitions, biomes or loot tables differ from the committed count or hash, so a pack bump is reviewed and re-recorded rather than accepted silently.

#### Scenario: Pack data changes
- **WHEN** the samples submodule moves and the generated actor definitions change
- **THEN** `build_generated_pack_data_matches_committed_manifest` fails and asks for `--manifest-only` after review

#### Scenario: Current counts
- **WHEN** the committed manifest is read
- **THEN** it lists 410 actor component registry names, 128 actor definitions, 89 biomes and 508 loot tables

Evidence: crates/unastar-data/output/pack-manifest.json, crates/unastar-data/tests/pack_data.rs (`build_generated_pack_data_matches_committed_manifest`), crates/unastar-data/datagen/src/manifest.rs

### Requirement: Embedded data decoded once at startup
Each embedded family SHALL be decoded at most once per process, on first use, into immutable shared data, and gameplay MUST read the decoded typed values rather than raw pack files. A decode failure of embedded data MUST panic with the family name, since the build produced it. Actor definitions MUST be re-validated through the shared actor loader and MUST decode with no diagnostics.

#### Scenario: Shared decoded values
- **WHEN** `actor_definitions::vanilla()`, `biomes::vanilla()`, `loot::vanilla()` or `items::vanilla()` is called twice
- **THEN** both calls return the same process-wide data decoded the first time

#### Scenario: Embedded actor rows are already normalised
- **WHEN** the embedded actor definitions are decoded
- **THEN** a row that is skipped or carries diagnostics panics instead of being loaded

Evidence: crates/unastar-data/src/actor_definitions.rs (`vanilla`, `parser`), crates/unastar-data/src/loot.rs (`vanilla`), crates/unastar-data/src/biomes.rs (`vanilla`), crates/unastar-data/src/items.rs (`vanilla`), crates/unastar-data/src/shapes.rs (`TABLE`), crates/unastar-data/tests/pack_data.rs (`actor_components_have_no_invented_defaults`)

### Requirement: Source manifest and attribution
`output/manifest.kdl`, written by `unastar-data-gen` and embedded as `source::SOURCE_MANIFEST_KDL`, SHALL record for every source its path, kind, version, confidence and content hash, plus the git commit where one exists. Text inputs MUST be hashed with CRLF folded to LF and binary inputs verbatim, so native input hashes equal protocolgen's `data/source/lock.json` on any checkout. A BDS capture artefact MUST NOT be listed without the capture that produced it.

#### Scenario: Line endings do not change hashes
- **WHEN** the same JSON is hashed with LF and with CRLF line endings
- **THEN** the hashes are equal, while a lone CR or a CR in a file with NUL bytes changes the hash

#### Scenario: Native hashes match the protocolgen lock
- **WHEN** every `inputs/1.26.51/native/` entry of the protocolgen lock is hashed
- **THEN** each hash equals the lock's digest

#### Scenario: Capture provenance
- **WHEN** a BDS packet artefact exists in `output/` but no `--bds-extraction` capture was supplied, or the capture did not produce it
- **THEN** manifest generation fails

Evidence: crates/unastar-data/datagen/src/manifest.rs (tests `hash_path_ignores_checkout_line_endings_but_not_binary_bytes`, `native_input_hashes_match_protocolgen_source_lock`, `collect_artifacts_rejects_bds_artifact_without_capture_source`, `collect_artifacts_rejects_bds_artifact_not_present_in_capture`, `render_manifest_includes_sources_and_artifacts`), crates/unastar-data/src/source.rs (`SOURCE_MANIFEST_KDL`; test `manifest_is_embedded`), crates/unastar-data/datagen/tests/bds_pipeline.rs (`bds_only_cli_writes_packet_artifacts_and_manifest_provenance`)

### Requirement: Native block palette and network hashes
Blocks SHALL come from protocolgen's native BDS 1.26.51 canonical block states in unaltered canonical order: a block's runtime ids are a contiguous range of palette ordinals, and `by_runtime_id` and `get` are the lookup contracts. Each state MUST carry BDS's hashed network id, equal to 32-bit FNV-1a of the state's little-endian `{name, states}` NBT. `unastar-data-codegen` MUST reject duplicate identifiers, non-contiguous or out-of-order ranges and out-of-range defaults.

#### Scenario: Palette ordinals
- **WHEN** `minecraft:stone`, `minecraft:wooden_door` and `minecraft:air` are looked up
- **THEN** stone's default state is 3317, the door spans 7380 to 7411, air's default is 17025, and runtime id 22091 is unknown

#### Scenario: Every hash re-derives
- **WHEN** each of the 22,091 states is encoded as `{name, states}` little-endian NBT and hashed
- **THEN** every result equals that state's stored network hash

Evidence: crates/unastar-data/tests/native_registries.rs (`block_lookup_uses_1_26_51_palette_ordinals`, `block_physics_use_native_measurements_not_prismarine_scaling`), crates/unastar-data/tests/network_hashes.rs (`every_state_hash_is_fnv1a_of_its_little_endian_state_nbt`), crates/unastar-data/datagen/src/blocks.rs (test `palette_uses_native_1_26_51_ordinals_and_network_hashes`), crates/unastar-data/codegen/src/blocks.rs (tests `rejects_duplicate_identifiers`, `rejects_non_contiguous_runtime_ranges`, `out_of_order_states_are_rejected`, `rejects_default_state_id_outside_range`, `rejects_non_zero_first_runtime_id`)

### Requirement: Native items, biomes and shapes
Items SHALL keep their native signed network ids, stack limits, typed properties and tags, with reviewed class corrections applied by datagen; registry component NBT MUST be kept byte-exact. Biomes MUST take their ids and definitions from native data and only add pack components; a pack biome without a native id MUST fail the build. Collision, outline and liquid-clip shapes MUST equal protocolgen's catalog for every state, with unavailable shapes kept distinct from empty ones.

#### Scenario: Items
- **WHEN** the item table is read
- **THEN** it has 2,076 items, `minecraft:acacia_button` has network id -140, and `minecraft:bucket` stacks to 16 from the corrections

#### Scenario: Biome wire ids
- **WHEN** `minecraft:sulfur_caves` and `minecraft:dappled_forest` are looked up
- **THEN** their ids are 194 and 195

#### Scenario: Shapes
- **WHEN** the shape table is compared with the protocolgen catalog state by state
- **THEN** every collision, outline and liquid-clip shape matches

Evidence: crates/unastar-data/tests/native_registries.rs (`native_items_preserve_signed_network_ids_and_typed_properties`, `item_class_stack_limits_and_inventory_capabilities_come_from_corrections`, `new_native_biomes_keep_their_wire_ids`), crates/unastar-data/datagen/src/pmmp.rs (tests `registry_component_nbt_is_kept_byte_exact_and_empty_data_is_omitted`, `corrections_fail_on_changed_base_values_and_unknown_inputs`), crates/unastar-data/build/biomes.rs, crates/unastar-data/tests/shapes.rs (`shape_table_equals_protocolgen_catalog_for_every_state`), crates/unastar-data/src/shapes.rs (test `decode_keeps_unavailable_distinct_from_empty`)

### Requirement: No invented defaults
Pack-derived data SHALL contain only what the sources state. Actor definitions MUST NOT gain components or fields their pack file lacks; published Mojang schema defaults MUST be exposed separately through `component_field_default`, keeping `false` and `0` defaults and leaving absent defaults absent. A cyclic schema reference MUST be an error, not a guessed default. Every typed vanilla component body MUST decode, and unknown fields in typed bodies MUST be rejected.

#### Scenario: Pack bodies stay as written
- **WHEN** `minecraft:arrow` and `minecraft:cow` are read
- **THEN** the arrow has no `minecraft:health` or `minecraft:inventory`, and the cow's panic goal keeps priority 1 and its family list `["cow", "mob"]`

#### Scenario: Schema defaults
- **WHEN** a schema default is `false` or `0`, or a schema reference is cyclic
- **THEN** the default is kept as that value, and the cyclic reference fails

Evidence: crates/unastar-data/tests/pack_data.rs (`actor_components_have_no_invented_defaults`), crates/unastar-data/tests/component_schema_defaults.rs (`numeric_schema_versions_and_referenced_defaults_preserve_false_and_zero`, `cyclic_schema_reference_is_an_error_not_an_invented_default`), crates/unastar-data/tests/actor_components.rs (`every_typed_vanilla_component_body_decodes`, `component_names_round_trip_and_cover_every_vanilla_definition`), crates/unastar-data/src/actor_definitions.rs (`component_field_default`)

### Requirement: Measured BDS facts with recorded method
Facts BDS keeps in code (armour slots and values, fuel burn times, attack damage, mining ticks, block drops, built-in recipes, legacy recipe identities, potion aux values) SHALL come from measurements of BDS 1.26.51 committed under `data/measured`, and `data/measured/manifest.json` MUST record each file's SHA-256, the BDS version, the harness revision and the method. Consumers MUST read these files rather than wiki tables or values derived from item names.

#### Scenario: Armour formula against measurements
- **WHEN** the armour damage formula is applied to every measured hit in `armor_values.json`
- **THEN** it reproduces each measured health loss

#### Scenario: Measured slots
- **WHEN** an item's armour slot is queried
- **THEN** it comes from the measured table, not from the item's name

Evidence: crates/unastar-data/data/measured/manifest.json, crates/unastar-data/data/measured/README.md, crates/unastar-data/src/armour.rs (tests `measured_defence_per_item`, `formula_reproduces_every_measured_hit`, `toughness_lies_in_every_measured_interval`), crates/unastar-data/src/equipment.rs (test `measured_slot_and_defense_are_not_derived_from_item_names`), crates/unastar-data/src/fuel.rs (test `measured_fuels_scale_with_the_cook_interval`), crates/unastar-data/src/melee.rs (test `measured_weapons_and_the_empty_hand`)
Verified by: `crates/bds-sweep` + `tools/bds-sweep` (`sweep.py`, `summarize.py`)

### Requirement: Captured BDS packets as committed artefacts
Facts BDS sends at join SHALL be committed only from real BDS 1.26.51 captures made with `crates/bds-extractor`: actor identifiers, `AvailableCommands`, game rules and `/help` usage. Each artefact MUST record its capture source, and the runtime MUST rebuild the packets from them so the result can be compared byte for byte with the capture.

#### Scenario: Actor identifiers
- **WHEN** the runtime builds `AvailableActorIdentifiers` from the registry
- **THEN** its identifier list equals the committed BDS 1.26.51 capture

#### Scenario: Commands and game rules
- **WHEN** the committed command and game-rule artefacts are decoded
- **THEN** they validate and every captured syntax resolves

Evidence: crates/unastar-data/output/actor_identifiers.json, crates/unastar-data/output/available_commands.json, crates/unastar-data/output/game_rules.json, crates/unastar-data/src/commands.rs (test `captured_syntax_decodes_and_resolves`), crates/unastar-data/src/game_rules.rs (test `captured_rules_decode_with_bds_defaults`), crates/unastar-data/src/actor_identifiers.rs (test `actor_types_cover_every_captured_identifier`), crates/unastar/src/registry/entity.rs (test `available_identifiers_equal_bds_1_26_51_byte_for_byte`), crates/unastar/src/registry/item.rs (test `vanilla_item_registry_packet_matches_bds_capture`)
Verified by: `crates/bds-extractor`

### Requirement: Comparison of samples against a BDS install
With `UNASTAR_BDS_DIR` set, `tests/bds_pack_diff.rs` SHALL compare the samples' item, recipe and loot-table documents with the BDS install's layered packs as canonical JSON, and every difference MUST equal the reviewed list in `data/bds_pack_diff.json`. It MUST check the samples version, commit and clean checkout and the BDS pack version against the recorded pins. Binary `7fMCB` documents MUST be matched by exact origin and SHA-256, never guessed. There MUST be no bless mode.

#### Scenario: Precedence rules
- **WHEN** recipes with one identifier appear in several layers or kinds
- **THEN** the first loaded wins regardless of `format_version`, while a later item layer replaces an earlier item

#### Scenario: No install configured
- **WHEN** `UNASTAR_BDS_DIR` is unset
- **THEN** the comparison prints a skip message and passes

Evidence: crates/unastar-data/tests/bds_pack_diff.rs (`bedrock_samples_compare_all_readable_bds_documents`, `first_recipe_identifier_wins_across_kinds_regardless_of_format_version`, `binary_paths_are_not_guessed_identifiers_or_silently_equal`, `priority_layers_do_not_reverse_archive_entry_order`, `last_item_identifier_wins_without_format_version_selection`), crates/unastar-data/data/bds_pack_diff.json
Verified by: `cargo test -p unastar-data --test bds_pack_diff` with `UNASTAR_BDS_DIR` set (local only)

### Requirement: Identifier-keyed registries open until frozen
Data families SHALL be keyed by identifier and loaded into registries that accept extra or replacing rows before they are frozen and shared. Replacing an actor definition MUST replace the whole definition, never merge components. Recipes MUST keep the first loaded identifier, so higher-priority pack rows are passed first. Loading addon packs from disk is not implemented (parity row `platform.addons` in [systems.toml](../../../docs/parity/systems.toml)).

#### Scenario: Whole-definition replacement
- **WHEN** an addon registers a `minecraft:cow` definition with no components before freeze
- **THEN** the frozen registry returns the replacement with no components, and other actors are unchanged

#### Scenario: First recipe identifier wins
- **WHEN** two furnace recipes named `addon:smelt` are loaded in order
- **THEN** the first one's result is used

Evidence: crates/unastar/src/registry/entity.rs (`ActorDefinitionRegistryBuilder::register`, `ActorDefinitionRegistryBuilder::freeze`; test `addon_registration_replaces_the_entire_definition_before_freeze`), crates/unastar-data/src/recipes.rs (`RecipeRegistry::with_items`; test `addon_recipe_load_order_keeps_the_first_identifier`), crates/unastar-rules/src/loot/mod.rs (`LootTables::insert`), crates/unastar/src/registry/item.rs (test `identity_resolution_keeps_legacy_variants_and_exact_numeric_addons_distinct`)

# BDS quirks we copy on purpose

unastar copies BDS 1.26.51 exactly, including behaviour that looks permissive, odd or
buggy (decision D3 in `thoughts/shared/plans/2026-10-24-data-driven-decisions.md`).
Every such behaviour is listed here so it can be revisited one at a time.

| Area | Behaviour BDS shows | How it was observed | Why it looks odd | unastar status |
|---|---|---|---|---|
| World / time | Time is synced only with `SyncWorldClocksPacket`; `SetTime` is never sent | 0 `SetTime` vs 54 `SyncWorldClocks` across 14 captured BDS 1.26.51 sessions (`tools/client-diff/conformance-report.md:121`) | Older servers and most third-party servers drive the client clock with `SetTime`; 26.x moved time to a world-clock registry | Planned (world W10); the re-sync cadence still needs a capture with the daylight cycle running |
| World / spawn | `level.dat` stores `SpawnY=32767` and the real spawn Y is resolved later | Seed-12345 reference world behind `crates/unastar/tests/fixtures/bds_1_26_51_seed_12345.json` (`SpawnX=103, SpawnZ=-28, SpawnY=32767`) | A sentinel height is persisted instead of a real block position | Planned (world W3) |
| World / generation | Forced ticking areas do not persist every requested chunk; on a first pass about half of the requested areas were missing on disk after `stop` | Generating the seed-12345 reference world (`examples/bds_worldgen_reference.rs` reports missing chunks) | `tickingarea add … true` suggests the area is generated and saved | Tooling only: the fixture dumper skips missing chunks; not copied into unastar |
| World / features | Feature JSON names blocks by pre-flattening identifiers and legacy states (`minecraft:log` + `old_log_type`, `minecraft:leaves` + `old_leaf_type`, `minecraft:grass`) | `definitions/features` and `features.brarchive` in the BDS 1.26.51 install | The network and world format use flattened names; the server upgrades legacy names when loading features | Done (WG-BEDROCK): `unastar_bedrock_codegen::blocks::LEGACY_BLOCKS`/`STATE_RENAMES` upgrade names at build time; unknown legacy values fail the build |
| World / features | The newest copy of `minecraft:overworld_underground_coal_ore_feature` has `iterations: 0`, so that rule places nothing | Versioned `vanilla_*` feature packs in the BDS 1.26.51 install | A shipped vanilla rule that is effectively disabled by override rather than removed | Done (WG-BEDROCK): the stack resolves to the zero-iteration copy and the rule is compiled out as disabled |
| World / features | `definitions/features` and `definitions/feature_rules` hold the oldest copies: every identifier they share with a versioned pack is overridden by the pack (59 features, 94 rules), so the stack is `definitions` < `vanilla` < `vanilla_<version>` ascending | Set difference over the BDS 1.26.51 install: no overlapping definition equals its pack copy, and the pack copies carry the newer shapes (e.g. coal ore rules) | A directory named `definitions` reads like the authority but is the base layer | Done (WG-BEDROCK): `packs::PackStack` |
| World / features | Old data values survive inside states: `{"name": "minecraft:stone", "states": {"stone_type": 0}}` (integer), and `minecraft:big_dripleaf` uses the removed `direction` int instead of `minecraft:cardinal_direction` | Resolved 1.26.51 feature documents | Mixed string and integer encodings of the same legacy state in one data set | Done (WG-BEDROCK): integer variants index the alias table; `direction` 0-3 maps to south/west/north/east |
| World / structure templates | Shipped bastion `.nbt` stages still use `minecraft:chain`, but the 26.51 native palette only has `minecraft:iron_chain` (pillar-axis y/x/z) | Local vanilla bastion stage files and protocolgen native canonical states; three of fourteen stage conversions failed before the alias fix | Reading the BDS install does not eliminate historical block-name upgrades, even for Java-format template files | Added the template-name upgrade; deterministic axis-preserving regression fails before/passes after, and all fourteen local stage variants convert afterward. No legacy placement/weight parity claim |
| World / features | Scatter numeric constants and Molang strings are both relative to the input: literal `"1"` at x=128 places at x=129, and a nested random scatter stays beside its parent's offset | Authored seed-12345 marker controls at x=-128, 0, 128; `bds_1_26_51_feature_coordinates.json` | Disproves the earlier absolute-Molang hypothesis; the claimed near-origin eyeblossom consequence was never observed and is withdrawn | Fixed `emit/scatter.rs`; an executable emitted-Rust placement regression fails before and passes after |
| World / features | Scatter uniform extent `[0,16]` placed markers at offsets 0 through 15, never 16, in 128 attempts at each of three origins | Same authored BDS marker fixture, iron blocks at y=285 | Uniform extents are upper-exclusive, unlike the previous inclusive runtime sampler | Fixed `scatter::uniform`; executable emitted-Rust boundary regression fails before and passes after. Other distribution formulas and draw-order parity remain unmeasured |
| World / features | Molang coordinate offsets round to nearest, with half ties away from zero, before adding the input coordinate: ±1.25 → ±1, ±1.75 → ±2, ±1.5 → ±2 | Expanded 22-case authored marker fixture at origins -128, 0, 128 | Flooring offsets was wrong; rounding the translated coordinate would also disagree at negative-origin half ties | Fixed build-time constant folding and runtime coordinate conversion; emitted-Rust regression fails before and passes after. Iteration counts and distribution-bound conversions are unchanged |
| World / feature queries | With isolated stone at y=250 and water at y=255, `query.heightmap` returns 256 and `query.above_top_solid` returns 251. Repeating the queries inside a y=280 parent fails placement beyond the world ceiling rather than rebasing the query result | Same expanded marker fixture, white/grey markers and the saved BDS command outcomes | Heightmap includes fluids; above-top-solid skips them. Both queries return world-space heights even though scatter expressions are relative offsets | Fixed both proto and decorating-region heightmap implementations; actual adapter regression reproduces 251 instead of 256 before the fix and passes after. Other material classifications and noise remain unmeasured |
| World / base rocks | In four seed-12345 chunks, bedrock forms contiguous columns 2–5 blocks thick from y=-64 (both -64 and -63 are fully bedrock). Stone is absent through y=0; stone/deepslate mix at y=1..7; deepslate is absent at y>=8 in the sampled layers | Offline `bds-recon` world, chunks (6,-4), (6,-3), (7,-4), (7,-3); `bds_worldgen_reference --geology` exports `bds_1_26_51_seed_12345_geology.json` (1,024 columns) | Bedrock's deepslate transition lies above y=0, unlike Java's surface rule; the shared noise core alone emits neither this base layer nor bedrock | Implemented topology/boundaries in `bedrock/geology.rs`, regression reproduced missing foundation before fix; uniform thickness and linear transition fit counts but RNG distribution, draw order/seeding and cross-seed generality remain unmeasured: to confirm by BDS fixture |
| World / ticking | Expected: random-tick count per chunk scales with the highest non-empty sub-chunk (`randomTickSpeed × floor(2.5 × (top + 1))`), positions come from one global LCG shared by all chunks, and the default `randomtickspeed` is 1 | Expected vanilla behaviour, to be confirmed by a BDS sweep before W11 ships | Java ticks 3 positions per section with a default of 3; a server-wide LCG makes tick positions depend on chunk processing order | Unconfirmed; planned (world W11) |
| Containers | The reply to a client `ContainerClose` carries container type `NONE` (-9, byte `0xf7`), not the type of the window being closed, and `server_initiated_close = false`. | BDS 1.26.51 capture, 2026-10-24: gophertunnel-fork client opens its inventory (`Interact` OpenInventory) and sends `ContainerClose{window 0, type 0xff}`; fixture `crates/valentine/tests/fixtures/conformance/wire_probe.jsonl` (`container_close_reply`). | The window being closed is the inventory (-1); BDS answers with a type that never opens anything. | Copied: `unastar` `handle_container_close` replies with `NONE` (test `inventory_open_and_close_use_bds_container_types`). |
| Containers | The player's own inventory opens as window id 2 on a fresh connection, and BDS answers a `ContainerClose` for window 0 with its own window id 2. | Same capture (`container_open_inventory`, `container_close_request`, `container_close_reply`). | The client's close names window 0; BDS ignores that and echoes the id it allocated. | Not copied yet: unastar opens the inventory as window 0, so request and reply agree. Revisit with the window-id counter (inventory engine slice). |
| Inventory | `CraftRecipeAuto` is only accepted while the inventory screen is open (status 7 `InvalidCraftRequest` when closed), when the request's ingredient descriptors match the recipe's (an `item_tag` descriptor for an item-name recipe gives status 25), and when ingredients are consumed from `CombinedHotbarAndInventory` (12); consuming the same slot through `HotBar` (28) gives status 27 and through `Inventory` (29) status 65. | BDS 1.26.51 probe, 2026-10-24: oak_planks recipe (net id 715), `/give @s oak_log 8`, creative; the accepted request/response are fixtures `craft_recipe_auto_request` / `_response`. | The hotbar slot holds the same stack under either container name; only the combined alias is accepted. | Not implemented (unastar answers every non-creative request with an error). |
| Network | `ItemRegistryPacket` lists items in an internal hash order (starts with `red_concrete_slab`, `bow`, `brain_coral_fan`), not by id or name. | BDS 1.26.51 capture `crates/unastar/src/registry/testdata/bds-1.26.51-item-registry.bin`. | Unordered; the client does not depend on it. | Not copied: unastar sends registry order; the entries themselves match byte for byte. |

# BDS quirks we copy on purpose

unastar copies BDS 1.26.51 exactly, including behaviour that looks permissive, odd or
buggy ([decision 0013](../decisions/0013-copy-bds-behaviour-exactly.md), formerly D3).
Every such behaviour is listed here so it can be revisited one at a time.

| Area | Behaviour BDS shows | How it was observed | Why it looks odd | unastar status |
|---|---|---|---|---|
| World / time | Time is synced only with `SyncWorldClocksPacket`; `SetTime` is never sent | 0 `SetTime` vs 54 `SyncWorldClocks` across 14 captured BDS 1.26.51 sessions (`tools/client-diff/conformance-report.md:121`) | Older servers and most third-party servers drive the client clock with `SetTime`; 26.x moved time to a world-clock registry | Planned (world W10); the re-sync cadence still needs a capture with the daylight cycle running |
| World / spawn | `level.dat` stores `SpawnY=32767` and the real spawn Y is resolved later | Seed-12345 reference world behind `crates/unastar/tests/fixtures/bds_1_26_51_seed_12345.json` (`SpawnX=103, SpawnZ=-28, SpawnY=32767`) | A sentinel height is persisted instead of a real block position | Planned (world W3) |
| World / generation | Forced ticking areas do not persist every requested chunk; on a first pass about half of the requested areas were missing on disk after `stop` | Generating the seed-12345 reference world (`examples/bds_worldgen_reference.rs` reports missing chunks) | `tickingarea add … true` suggests the area is generated and saved | Tooling only: the fixture dumper skips missing chunks; not copied into unastar |
| World / storage | Saved sub-chunk records are read leniently. The version-9 y byte is ignored and the key's y decides where the blocks go. A palette may list more entries than its bit width can index. Bytes after the last storage are skipped. A record with zero storages is all air | Records edited in a saved flat world, then reloaded and checked with `/testforblock` (2026-11-10; every edit and answer is listed in `docs/solutions/storage/bds-subchunk-palettes-are-nbt-block-states.md`): y byte 5 under key y 0 loaded at y 0; a 1-bit storage with 3 entries, 8 trailing bytes and `[9, 0, y]` all loaded | The y byte repeats the key, and a palette longer than its width is malformed; a strict reader rejects both | Copied (`crates/unastar/src/world/chunk.rs` tests `record_framing_follows_the_key_not_the_y_byte`, `palette_lengths_are_positive_and_may_exceed_the_bit_width`, `two_storage_wire_versions_replace_both_layers_and_reject_partial_commits`). Entries the width cannot index are dropped |
| World / storage | Damaged palette data loads with substitutes. An index past the palette reads as the palette's first entry. An unknown block name becomes a placeholder that keeps the name. An unknown, missing, extra or mistyped state resolves to some state of the block. A truncated last entry still loads. A zero-bit storage with a length field or a `0xFF` header reads as air. A 7-bit storage stops the server. BDS never writes any of these, and it leaves the bytes on disk until the chunk changes | Same edited-record sessions (edits and answers in the same note): indices 2 and 3 of a `[gold, diamond]` palette read gold; `minecraft:not_a_block` read as `%tile.not_a_block.name`; `pillar_axis="w"` read as an oak log; the 7-bit session exited while loading. None of the 938 records BDS saved in the fixture worlds has any of these | Silent substitution hides corruption, and a save after an edit would replace the original bytes | Not copied: such a record fails its column's load and stays on disk (world-storage spec; `chunk.rs` test `indices_outside_the_palette_are_errors_not_panics`, `chunk/persistent.rs` tests). BDS also reads a runtime-form storage (header bit 1) as air; unastar saved sub-chunks that way before it wrote BDS's form, and still loads such a storage and rewrites it in BDS's form the next time its column is saved (world-storage spec) |
| World / storage | A section changed since it was read is saved with the palette entries no cell uses dropped (the rest keep their order, at the smallest width that holds them, 0 bits for one entry) only when its chunk unloads or the server stops, and only if that narrows the bit width.
